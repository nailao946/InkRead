# InkRead 墨读 — 视频与文章生词量（浏览器扩展）

给**哔哩哔哩 / YouTube 的视频**和**普通网页的英文文章**算一笔账：
**这段材料对我（你的墨读词库）来说，有多难？值不值得读？**

- **三套可切换的评级体系**：阶梯 L1–L4（看「对你」） / CEFR A1–C2（看文本） / 蓝思 Lexile（看文本）
- **视频字幕逐词标记**：YouTube / 哔哩哔哩 的**播放器字幕**逐词上色（生词红 / 在学蓝 / 未收录橙），**对着字幕点词**就看离线释义、直接改标记
- **网页正文直接上色**：不用进阅读模式，打开文章就能看到哪些词没掌握（只标生词，已知词不动）
- **标记与划线**：点词标记「生词本 / 在学 / 已学」，选中句子划线留痕——像微信读书那样
- **阅读模式**：把网页正文搬进干净的覆盖层，按你的词库**逐词着色**，**点词即查离线释义**
- **词组识别**：内置 2.4 万条常用词组，正文里整组画**一条不断的线**，点词组给整组中文 + 「分开看各词」
- **段落翻译**：每段末尾一个「译」，一键出中文（译文按句分行）；翻译接口与墨读 PC 端**共用一份配置**
- **i+1 推荐**：95–98% 为「理想区」，直接告诉你「符合 i+1」还是「超出当前水平」
- **客观难度**：脱离个人词库，只看用词本身的词频分层与蓝思值
- **高频生词榜**：按出现次数排序，先攻这些收益最大

支持 **Chrome / Edge / Firefox**，同一套代码（Manifest V3）。

## 1. 安装

### 先打包（`dist/` 是构建产物，未入库）

```bash
node plugin/build.mjs              # 全量：dist/chrome、dist/edge、dist/firefox + 三个 zip
node plugin/build.mjs chrome       # 只打 Chrome/Edge
```

### Chrome / Edge

1. 打开 `chrome://extensions` 或 `edge://extensions`
2. 打开右上角 **开发者模式**
3. **加载已解压的扩展程序** → 选 `plugin/dist/chrome`
   （开发期也可以直接选 `plugin/` 目录本身，改完点「重新加载」即可）

### Firefox

1. 打开 `about:debugging#/runtime/this-firefox`
2. **临时载入附加组件** → 选 `plugin/dist/firefox/manifest.json`
3. 长期使用需签名：`npx web-ext build --source-dir plugin/dist/firefox`
   （Firefox 与 Chrome 的差异只在清单：Firefox 用 event page 而非 service worker，
   所以 `manifest.firefox.json` 单独一份；打包脚本会自动改名成 `manifest.json`。）

> **权限说明**：扩展申请了「读取你在所有网站上的数据」——这是**网页文章分析与上色**必需的
> （要抽正文才知道有多少生词）。它对页面只做一件事：把正文里的英文单词**包进一层 `<span>`**
> 好给它上色/划线（关掉上色会立刻拆掉、逐字还原）。**不修改页面上的任何文字内容、
> 不提交表单、不上传任何数据**；词库、标记、划线全部只存在本机浏览器里。
> 不想给这个权限的话，把 `manifest.json` / `manifest.firefox.json` 里第二个
> `content_scripts` 条目（匹配 `http://*/*`、`https://*/*` 的那个）删掉，重打包即可，
> 视频功能不受影响。

## 2. 三套评级体系

同一份分析结果，三把尺子量的东西**不一样**，切换只是换个视角：

| 体系 | 看什么 | 主指标 | 适合 |
|---|---|---|---|
| **阶梯 L1–L4** | **对你** | 可理解度（已学 + 在学 的词次占比） | 决定「现在要不要读这个」；95–98% 是 i+1 理想区 |
| **CEFR A1–C2** | 看文本 | 前 2500 高频词覆盖率 | 跟教材 / 考试 / 同学对齐，材料可以横向比较 |
| **蓝思 Lexile** | 看文本 | 平均词频对数 → `###L` | 对接北美图书与分级读物体系 |

三套**同时**算好并随报告缓存，所以在胶囊 / 面板里切换是**瞬时**的，不需要重新分析。
设置页可以定默认值，面板与阅读模式里都能随手切。

### 阶梯 L1–L4（与墨读阅读端同口径）

**可理解度** = （已学词次 + 在学词次）÷ 总词次，按**词次**统计（与阅读端 `computeBookStats` 同口径）：

| 等级 | 可理解度 | 区间 | 建议 |
|---|---|---|---|
| L1 轻松 | ≥ 98% | 自由阅读区 | 可当泛看/精听，词汇收益有限 |
| **L2 适中** | **95–98%** | **i+1 理想区** | **最值得读：生词占比恰到好处** |
| L3 偏难 | 90–95% | 教学挑战区 | 先扫一遍高频生词，或配合字幕精看 |
| L4 困难 | < 90% | 挫败区 | 不建议硬啃，换更简单的内容 |

### CEFR A1–C2（客观用词难度）

按「前 2500 高频词覆盖率」分 6 档（是原有 L1–L5 客观难度的六档细化）：

| CEFR | 前 2500 覆盖率 | 说明 |
|---|---|---|
| A1 | ≥ 0.94 | 几乎全是最高频词汇，短句为主 |
| A2 | ≥ 0.87 | 日常话题，用词常规 |
| B1 | ≥ 0.75 | 能读懂要点，需要一定词汇量 |
| B2 | ≥ 0.62 | 抽象话题与低频词明显增多 |
| C1 | ≥ 0.46 | 书面/专业语域，术语密集 |
| C2 | < 0.46 | 接近母语学术/文学材料 |

### 蓝思 Lexile（客观词频难度）

MetaMetrics 的官方公式**未公开**，也没有可离线使用的官方计算器。
这里用的是公开研究里常见的**平均词频对数（mean log word frequency）**近似法：

1. 每个词取语料词次的对数 `log10(count)`（表外词按 `OOV_COUNT = 200` 计）
2. 混合两个口径：**全部词 0.45 + 实词（band ≥ 2）0.55**
   —— 只算功能词会把口语文本的难度整体压平，只算实词又会高估短句难度
3. 用一组锚点做分段线性插值，锚点取自公开的蓝思—学段对应关系

校验样本（`node plugin/tools/calibrate-rating.mjs` 可复跑）：

| 样本 | 核心占比 | 蓝思 | 学段 | CEFR |
|---|---|---|---|---|
| 儿童句子 | 0.964 | 384L | 小学低段 | A1 |
| 日常 vlog | 0.939 | 516L | 小学高段 | A2 |
| TED 演讲 | 0.857 | 732L | 初中 | B1 |
| 新闻社论 | 0.471 | 1304L | 大学/成人 | C1 |
| 学术论文 | 0.370 | 1435L | 母语高难 | C2 |

> ⚠️ 这是**估算值**，不是 MetaMetrics 认证的官方蓝思值。它用来做**相对比较**（这篇比那篇难多少、够不够你的水平）足够可靠；要拿去做正式分级请以官方测量为准。
> 词频表缺少 `counts` 字段时（旧数据文件），蓝思会明确显示为不可用，而不是乱给一个数。

分词、词形还原、覆盖率算法**逐行对齐** `web/js/util.js` 与 `web/js/reader.js`——
所以一个视频、一篇网页文章和一本电子书的 L1–L4 可以直接横向比较。

## 3. 视频字幕：逐词标记

在 **YouTube / 哔哩哔哩** 的视频页，除了右上角的评级胶囊，扩展还会**直接接管播放器字幕**：

- **逐词上色**——生词（红 + 下划线）/ 在学（蓝 + 下划线）/ 未收录（橙 + 虚线下划线）/ 已学（保持原样）。
  每条字幕换行都会被重新着色，所以一整集的生词是**连续标出来**的，不是一帧一帧闪。
- **对着字幕点词**——弹出释义卡片（音标 + 中文释义 + 当前状态），可直接改成
  **生词本 / 在学 / 已学**（再点一次＝取消）。和网页正文用**同一份词库、同一套状态语义**。
- **词库没联动就不着色**——空词库时每个词都会算「生词」，满屏橙点反而看不清字幕，
  所以扩展宁可不着色，等词库接上再上色。
- **样式两档**：`着色 + 下划线`（默认，字幕背景复杂时最稳）/ `加半透明底色`（画面花时对比更强）。
  字幕上的字还带**描边阴影**，压在亮画面上也读得清。
- **不破坏播放器**——只把字幕里的文本节点拆成 `<span>`，**不整段重建字幕、不改容器结构与排版**；
  点击事件用 capture 阶段截获（否则会被播放器的「点一下暂停」吃掉），只拦下**被点中的那个词**；
  关闭开关或扩展停用时**逐字还原**字幕，不留痕迹。

开关：设置页 →「分析偏好」→「字幕逐词标记」；也可以在视频页胶囊面板里一键开关。

> 字幕标记与内置的**字幕抓取**是两回事：前者是「在播放器上标词」，后者是「把字幕文本抓来分析生词量」。
> 即使关闭了自动分析，字幕标记依然工作。

## 4. 网页文章：上色 / 标记 / 词组 / 翻译 / 阅读模式

在普通英文网页上，扩展会：

1. **薄抽取正文**——优先 `<article>` / `main` / `[role=article]` 以及
   `.post-content` / `.markdown-body` / `.RichText` 等常见正文容器；
   排除 `nav/header/footer/aside/form` 等噪声；段落去重、压平空白。
   另外内置了**阅读器/期刊站点的专门规则**（微信读书 `weread.qq.com`、
   Z-Library / Anna's Archive / 豆瓣读书、Medium / Substack、NYT / Economist / New Yorker 等），
   正文不在 `<article>` 里也能抽对
2. **判断「值不值得分析」**——至少 **200 个英文词**、**≥3 段**、英文字母占比 **≥25%**
   （中文为主的页面直接给明确理由，不硬算）
3. **在右下角挂一个评级胶囊**，同时**直接在正文上着色**

### 4.1 网页正文直接上色（默认开启）

不用进阅读模式——分析完立刻把正文里的英文单词逐词着色：

- **只标没掌握的词**：在学（蓝）/ 生词本（红）/ 未收录（黄）
- **已学的词保持原样**——满屏着色比不标更伤阅读，这是刻意的
- 样式二选一：**下划线**（默认，最不扰人）/ **底色高亮**（深色页面上更醒目）
- 胶囊面板里一键开关；**关掉的站点会被记住**，下次不自动上色
- 长文**分帧增量**着色，不卡页面；站点后续加载的新内容（无限滚动）会自动补色
- 关闭开关会**立即拆掉全部 `<span>`、逐字还原**原始 DOM

> 着色用 CSSOM（`el.style`）而不是注入 `<style>`，因此**不受页面 CSP 的 `style-src` 限制**。

### 4.2 标记与划线（像微信读书那样）

- **点任意彩色词** → 弹出释义卡片，带音标、中文释义、以及该词在你词库里的状态
- 卡片上直接改状态：**生词本 / 在学 / 已学**（再点一次＝取消）。
  词级标记**全局生效、优先于墨读词库**——等于「手动校正词库」，会参与所有页面与视频的判定
- **选中一段文字** → 浮动工具条 → **划线**（可加笔记），划痕留在原文上，刷新后自动重放
- 面板底部有「**我的标记**」区：列出本页标记的词与划线，可一键改/删
- 全部只存本机浏览器；词标记全局、划线按 URL 分开存

### 4.3 阅读模式

把正文搬进干净的覆盖层读：

- 正文重排成干净版式（可调字号 13–26px，`A-` / `A+`）
- **逐词着色**：在学（蓝）/ **生词本**（红）/ 未收录（黄虚线）/ 其余为已学
- 「**只看生词**」按钮把「已学」的词压暗，集中攻生词
- **点任意词看释义**：走墨读自带的**离线英汉词典**（本地服务的 `/dict/<字母>.json`），
  带音标、中文释义、以及该词在你词库里的状态。**不需要联网，也不需要额外装词典。**
- **词组整组一条线** + 每段一个「**译**」（见下两节）

> 墨读没运行时：仍然着色，但点词会提示「未检测到墨读本地服务，无法查词」。

### 4.4 词组识别（2.4 万条离线词组）

阅读模式里，正文中的**常用词组会整组画一条不断的线**（而不是给每个词各画一条）：

- **数据驱动**：`data/phrases.json`——由墨读词库的 ECDICT 多词条目两级过滤而来（剔除领域术语、
  要求含功能词），**与网页版 `web/dict/phrases.js` 是同一份表的两个形态**（改一份必须用脚本重建另一份）。
- **识别规则**（与网页版逐字对齐）：从当前词出发查「首词索引」做**最长匹配**，词形先经
  `lemmas()` 还原（`tearing down` → `tear down`），分隔符**必须是纯空白**；
  同长度时让「基形」盖过「原形」（不同时态归到同一基形）。
- **只在组内有生词时才画线**——已掌握的词组不划线，不打扰阅读。
- **点词组** → 卡片给**整组中文**（优先离线词组库，没收录才走在线翻译），并带
  「**分开看各词**」：一键展开成词组里每个词的按钮，点进去看单词语义。
- 关闭开关（设置 → 翻译接口 →「离线词组库」）后不加载 950KB 的词组表、也不画线。

> **单实现原则**：词组匹配**只在后台 Service Worker 里做一次**，内容脚本通过 `phraseScan` 消息
> 拿「字符区间」自己渲染。原因是 MV3 内容脚本是经典脚本、不能 `import` ESM——如果在页面侧再写一份
> 匹配器，两处实现迟早漂移，出现「线画在这里、释义查的是另一组」的鬼故事。
> 也因为这个原因，950KB 的词组库**不进 `web_accessible_resources`**，不暴露给任意网站。

### 4.5 段落翻译（每段末尾的「译」）

- 阅读模式每段末尾一个 **「译」** 按钮（鼠标悬停段落时才显眼，平时不打扰阅读）
- 点一下 → 本段中文出现在段落下方，**译文按句分行**（一行一句更好读），并标注来自哪个引擎
- **再点「译」＝收起**；同一段**本会话内不重复调接口**（段落文本做键，120 段上限后整体清空）
- 走的是「墨读 PC 端同一套翻译接口」：优先**免费引擎**（Google / MyMemory / 必应），
  付费引擎（有道 / 腾讯 / 阿里 / 火山 / DeepL / 微软 / LibreTranslate）的 Key 可直接从墨读导入，
  请求经墨读本地服务的 `/__proxy` 转发（**零新增主机权限**，也不吃 CORS）
- 整段翻译受两个开关控制：设置 →「翻译接口」→「在线翻译」与「段落翻译」

## 5. 与墨读联动（决定「什么叫生词」）

扩展的「生词」定义完全来自**墨读词库**：`已学 = 认识`、`在学 = 半熟（计入可理解度）`、`生词本 = 生词`。
三种模式（设置页 → 词库联动），按需选择：

| 模式 | 说明 | 适合 |
|---|---|---|
| **自动联动词库** | ① 先试**直连存档目录**（绑过一次就一直有效，**不用启动桌面版**）；② 没有绑定时再探测墨读桌面版（127.0.0.1:17890…）或网页版 `start-server`（8642…），读存档目录里的 `vocab.json` | 默认；想要「改完词库即生效」 |
| **只用导入的词表** | 拖入墨读「导出备份」JSON / `vocab.json` / `vocab.csv` / 纯词表 txt；仍可叠加「存档目录直连」 | 没装墨读、或跨设备用一份词表 |
| **关闭联动** | 以空词库分析：所有词都算生词，只看「客观难度」 | 只想评估材料本身难度 |

> 词表缓存 30 分钟，点「重新同步」可立即拉取。

### 5.1 默认就对齐墨读那个目录

**推荐做法：点一下「用墨读的目录」。** 只要墨读（桌面版或 `start-server`）在跑，扩展就自动探测到它的
**存档根目录**，然后读的就是 **PC 端同一份 `<存档目录>/vocab.json`**——不用找文件夹、不用绑定、
天然满足「默认绑定目录 = PC 端存储目录」。

需要**不启动墨读**也能用（比如只想开浏览器）时，再手动绑定一次：

- 「设置 → 词库联动 → 存档目录直连 → **手动绑定目录…**」；选择器的**起始位置会跟着墨读的目录走**
  （墨读在「文档」下就用 `文档`，在桌面/下载就对应跟进）——浏览器不允许按绝对路径跳转，
  这是能做到的最大程度的「默认落到同一个目录」。
- 绑定后设置页会显示「**与墨读是否同一目录**」：一致会标 `是 ✓`，不一致会提示改哪个；
- 权限与目录句柄存进 IndexedDB（同源共享），**重启浏览器仍然有效**；
- 直连不可用（没绑定 / 目录里没有 `vocab.json` / 权限被收回）时，**自动回落到本地服务**，行为与以前完全一致。

### 5.2 一个位置、三端同步

`<存档目录>\vocab.json` 是唯一的词库真相，桌面版（WPF）、网页版、本扩展读写的是**同一个文件**：

```
   桌面版 WPF ─┐
   网页版 serve ├─→  <存档目录>/vocab.json  ←─  浏览器扩展（直连）
                ─┘        （唯一真相）
```

- **插件 → 桌面 / 网页**：在网页文章里点词标记「已学 / 在学 / 生词本」时，后台会把这一条**写回**
  `vocab.json`（只改该词的 `status` + `updatedAt`，保留释义等原字段；新词按墨读字段补全）。
  桌面版 / 网页版重开或点「设置 → 存储与存档 → **并入磁盘词库**」即可看到。
  这个写回可以用「标记写回共享词库」开关关掉。
- **桌面 / 网页 → 插件**：桌面版里改的词，插件下次同步（30 分钟 TTL 过期，或点「重新同步」）就能读到。
- **冲突规则**：两边都按 `updatedAt` 取较新的一份，**不会用旧数据覆盖较新的编辑**，也不会丢掉任一端独有的词。

> 实现要点：MV3 的 service worker 没有 DOM，File System Access 在它里面不保证可用。
> 因此目录句柄读写走「先试直连 → 不行就交给**离屏文档**（`src/offscreen/`，一个隐藏的扩展页面）」，
> 两个上下文都没有时（Firefox）自动退回本地服务 / 导入文件。设置页的「后台读写通道」会直接告诉你走的是哪条路。

**离线词典仍需本地服务**：阅读模式点词看释义走的是 `/dict/<字母>.json`（词典在程序目录里，不在存档目录），
所以「直连存档目录」只解决了**词库**；不启动墨读时仍会着色，但点词会提示无法查词。

### 5.3 翻译接口：与墨读共用一份配置

「设置 → 翻译接口」里的引擎配置形状**与墨读网页版 `settings.json` 的 `settings.api` 完全一致**，
所以可以一键 **「从墨读导入」**：连上本地服务 → 读 PC 端的 `settings.json` → 把已填好的
Key / Secret / Region 搬过来（**Key 只进扩展自己的 `chrome.storage.local`，不落任何文件、不上传**）。

- **13 个引擎**：有道智云 / 腾讯云 TMT / 阿里云百炼 / 阿里云机器翻译 / 火山方舟 / 火山机器翻译 v3 /
  火山机器翻译 / DeepL / 微软翻译 / LibreTranslate / 谷歌翻译 / 必应翻译 / MyMemory
- **免费优先**：默认 `自动`，按「已配置的官方接口 → MyMemory 兜底」的顺序试，全失败才报聚合错误
- **零新增主机权限**：请求统一走墨读本地服务的 `/__proxy?url=…&root=…` 转发（服务端的白名单已覆盖
  全部 13 个引擎），所以不需要在 `host_permissions` 里加任何翻译厂商域名，也不吃 CORS
- 设置页有「**连通性测试**」：拿 `hello` 走一遍当前引擎，直接告出用的是哪个引擎、返回什么

> 关掉「在线翻译」总开关后：段落「译」按钮不显示、词组卡片不自动在线翻译，但**离线词组库与离线词典照旧**。

## 8. 已知限制

- **视频需要字幕**。没有字幕时退化为「标题 + 简介」估算，面板会明确标注。B 站 AI 字幕通常需要登录。
- **YouTube「只读到标题」的真根因是 PoToken**：YouTube 自 2024–2025 起对 `/api/timedtext`
  强制要求 `pot`（Proof-of-Origin Token，来源证明令牌）。**缺 token 时不报错，而是返回
  HTTP 200 + 空 body** —— 于是静默退化成「标题+简介」。页面初始 `ytInitialPlayerResponse`
  里的 baseUrl 常带 `exp=xpe` / `potc=1` 标记（表示会走 PoToken 校验），直接请求必空。
- **字幕轨来源优先级**：① 活动播放器实例 `#movie_player.getAudioTrack().captionTracks`
  （**当前会话已签名**的 URL，多数带有效 pot）→ ② `getPlayerResponse()` → ③ 页面
  `ytInitialPlayerResponse` → ④ 都没有时用 **InnerTube `/youtubei/v1/player`（ANDROID 客户端）**
  再要一份（这份轨道对多数视频不要求 pot）。
- **每条轨生成多个 URL 候选**逐个尝试（`ytCaptionUrls`）：`fmt=json3` → 去掉 pot 标记的 json3 →
  原始 URL → 去掉 pot 标记的原始 URL。任一拿到非空内容即停。
- **抓取通道**：① 内容脚本**页面上下文**（同源、带 Cookie，与播放器取字幕一致）→ ② Service Worker 直连。
  每次页面尝试都挂 **AbortController 硬超时**，SW 侧对内容脚本消息再加一层竞速超时 —— 任何一条通道
  卡住都不会把分析挂死。凭据只用 `same-origin`（同源即带 Cookie）与 `omit`；**不用** `include`
  （对不回显凭据的跨域目标会长时间挂起）。
  面板头部会显示字幕来源（`播放器签名轨 / 播放器响应 / InnerTube 兜底`）与通道（`页面通道 / 后台通道`），
  一眼能看出内容是从哪一步拿到的。
- `srv3`（`<p><s>`）与 `srv1`（`<text>`）各有独立解析分支做兜底。
- **B 站只有中文字幕**时不会硬算：面板会直接说明「无法评估英文生词量」，并列出该视频现有的字幕轨。
- **自动生成字幕**（YouTube ASR / B 站 `ai-*`）噪声较大，用词统计会略偏，面板会标注「自动生成」。
- **文章抽取是启发式的**。正文不是 `<p>` 结构（纯 `<div>` 长文本、PDF 内嵌阅读器）或需要滚动才加载时
  可能抽不全，面板会给出「正文太短」之类的明确理由而不是硬编。
- **客户端渲染的站点（正文晚于首屏出现）会自动重试**：首探为空时退避重试（最多 10 次）+ 用
  `MutationObserver` 盯 DOM 变化，正文一出现就补做分析（如 ireadworld.com 这类 SSR + hydrate 的站点），
  无需手动刷新。重试与观察都有上限，不会在重页面里无休止空跑。
- **内联上色会往页面里插 `<span>`**（只包裹英文单词，不改文字内容）。极少数对 DOM 结构极度敏感的
  站点（自己维护 virtual DOM 且不认外部插入的节点）可能出现样式错位——把该站点的上色关掉即可
  （面板里的「网页上色」按钮会把站点记进黑名单）。
- **词组线目前只画在阅读模式里**。内联上色是「逐文本节点增量包裹」的，跨节点的词组会被拆到不同
  文本节点里（`<span>tear</span><b>ing</b>` 之类），硬拼回去既脆又慢；阅读模式是渲染期一次性决定的，
  所以只在那里画词组线——**这与墨读 PC 端的行为一致**（PC 端也只有阅读视图有词组线）。
- **字幕标记只作用于「播放器内字幕」**：YouTube 的 `ytp-caption-*` 与 B 站 bpx 播放器的
  `.bpx-player-subtitle-panel*`。如果站点换了播放器内核导致容器类名变了，会临时标不上
  （扩展只做「认识已知容器」这一件事，不猜）；第三方字幕扩展渲染的字幕不在范围内。
  无论标不标得上，扩展**都不会修改字幕文本**，关闭开关或停用扩展会**逐字还原**。
- **段落「译」与词的在线翻译**走墨读本地服务的 `/__proxy`。没连上墨读时：免费引擎（Google / MyMemory /
  必应）仍然直连可用，**付费引擎会被 CORS 拦**（设置页的「连通性测试」会直接告诉你通道状态）。
- **词组的「在线兜底」需要开启**「词组自动在线翻译」（设置 → 翻译接口）：离线词组库没收录的整组才走接口，
  免得每点一个词组都消耗一次额度。
- **划线按「选中的文本」重放**：页面内容改版后，找不到原句的划线不会被重新画出来（数据仍在，
  可以在面板「我的标记」里看到并删掉）。同一页面上重复出现同一句话时，固定标在第一处。
- **蓝思值是估算**（见第 2 节），MetaMetrics 官方公式未公开。
- **可理解度按词次统计**，因此高频功能词（the / of / to）会显著抬高覆盖率——这与墨读书籍难度口径一致，属刻意设计。
- Firefox < 128 不支持 `scripting.executeScript({world:'MAIN'})`，会自动走「扫描 `<script>` 标签」的兜底路径。
- **Firefox 没有 File System Access**，所以「存档目录直连」只在 Chrome / Edge 可用；
  Firefox 请用「自动联动」（跑桌面版 / `start-server`）或「导入文件」。设置页会直接把这条路标成不可用，不会假装能用。
- **目录句柄需要一次用户手势**：绑定必须在设置页点按钮完成（浏览器安全策略），装完扩展先点一次即可，之后长期有效。
  若在浏览器设置里清过站点数据 / 权限，重新点一下「立即读取」会再弹一次授权。
- **点词查释义仍需要本地服务**（离线词典在程序目录的 `/dict/*.json`，不在存档目录），
  「直连存档目录」只解决**词库**；不启动墨读时能着色、能标记，但点词看不到中文释义。
- **写回是「按词合并」，不是全量覆盖**：只改被标记那一条的 `status` / `updatedAt`，新词按墨读字段补全；
  状态没变化时**完全不写文件**（幂等，不会把 `vocab.json` 抖出 diff）。
  删除标记不会从 `vocab.json` 里删词（无法判断另一端是否还需要它），只是不再由插件覆盖其状态。
- **`vocab.csv` 不参与合并**：那是给人看的表格；程序之间同步只认 `vocab.json`。
  在 Excel 里改了 CSV 不会自动回流，需要走墨读的导入。
- 扩展只写**词库状态**这一处墨读数据（且可用开关关闭）；划线、分析缓存仍只存在浏览器本地。
- **悬浮胶囊位置按「屏幕比例」记忆**（不是绝对像素）：换分辨率 / 缩放后仍在相对同一位置；窗口过小时会被夹回可视区。
  拖动后位置存进 `iv.settings.ui.pos`，设置页有「重置悬浮位置」。点一下（不拖动）仍然是展开/收起。
- **文章页的悬浮胶囊同样可拖动**（与视频页一套实现），位置存进 `iv.settings.article.pos`，默认右下角；
  拖到另半屏 / 靠顶时面板自动改朝屏幕内侧展开。设置页的「重置悬浮位置」会同时复位视频与文章两处。
- **扩展更新后的自愈（无需手动刷新页面）**：扩展被重新加载 / 更新后，已打开页面里的**旧**内容脚本会被
  浏览器孤立（`chrome.runtime` 变 `undefined`，任何消息都抛 `Cannot read properties of undefined
  (reading 'sendMessage')`）—— 这正是「悬浮窗报通信失败、但点开扩展图标又能评估」的原因。
  现在扩展更新时会就地**重新注入**内容脚本，点扩展图标时若发现内容脚本收不到消息也会重注入再重试；
  旧脚本检测到上下文失效会自行摘掉胶囊让位，不会出现两个胶囊。
- **换行渲染**统一走 `escLines`（与 `web/js/util.js` 同口径）：词典释义里存的「字面量 `\n`」和真实换行
  都会被渲染成换行。改了这条口径，三端显示才会一致。
- **面板里「已经是 HTML」的片段不能再 `esc()`**：`allRatingsHtml()`（视频侧对应 `allRatings()`）返回值
  本身就含 `<b>`（用来加粗评级代码），调用处必须直接插入；再套一层转义就会显示字面的 `阶梯 <b>L4</b>`。
