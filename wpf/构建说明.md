# 墨读 InkRead — WPF 桌面壳构建说明

本目录是一个 **.NET 8 / WPF + WebView2** 桌面工程。

前端（`../web/`，含 51MB 词典分片）在**编译时全部内嵌进 `InkRead.dll`**：
运行时不依赖 web 文件夹、不依赖外部服务器，编译产物即为自包含应用。

内置的本地服务（`LocalServer.cs`）把内嵌资源以 `http://127.0.0.1:端口` 提供给 WebView2：

- **标准 http 源**：Service Worker、IndexedDB、Web Worker(pdf.js)、speechSynthesis 全部按标准行为工作
  （`127.0.0.1` 属于安全上下文）；
- **`/__proxy` 转发端点**：浏览器直连翻译接口会被 CORS 拦截，桌面版由此端点代发请求，
  因此**桌面版可直接使用有道、百度等官方接口**。

---

## 一、环境要求

| 组件 | 版本 / 说明 |
|---|---|
| Windows | 10 或 11（推荐 11） |
| .NET 8 SDK | 需安装（含 `dotnet` 命令）。VS 安装时勾选 “.NET 桌面开发” 工作负载会自动带上 |
| Visual Studio | 2022 17.8+（社区版即可），工作负载：**.NET 桌面开发** |
| WebView2 Runtime | **Windows 11 已内置**；Windows 10 需到微软官网下载安装 “WebView2 Runtime” |

---

## 二、用 Visual Studio 打开并编译

1. 用 VS 打开本目录下的 **`InkRead.slnx`**（VS 2022 17.10+ 新格式）
   或 **`InkRead.sln`**（传统格式，老版本 VS 用这个）；两者等价，任选其一。
   也可以直接双击 `InkRead.csproj`，VS 会自动生成临时解决方案。
2. 首次打开，VS 会提示 **还原 NuGet 包**（Restore）。也可在菜单
   `工具 → NuGet 包管理器 → 程序包管理器控制台` 执行：
   ```
   dotnet restore
   ```
   关键依赖：`Microsoft.Web.WebView2`（csproj 中已固定为 `1.0.2792.45`；
   若还原失败，可在 “管理 NuGet 程序包” 中升级到最新稳定版，建议 ≥ 1.0.2xxx）。
3. 顶部工具栏选择 **Debug / Release**、平台 **Any CPU**（或 x64）。
4. 按 **F5**（调试运行）或 **Ctrl+Shift+B**（仅生成）。
   生成产物在 `wpf/bin/Release/net8.0-windows/`：`InkRead.exe` + `InkRead.dll`（内含前端）+ WebView2 依赖。

## 二·补、不想装 VS？直接运行已编译的 exe

**无需 VS**：双击 `wpf/bin/Release/net8.0-windows/InkRead.exe` 即可（已编译，0 错误 0 警告）。
命令行重编译：

```bat
cd wpf
dotnet build InkRead.slnx -c Release
bin\Release\net8.0-windows\InkRead.exe
```

> 说明：前端资源通过 csproj 的 `EmbeddedResource` 打进程序集，
> **不再需要把 `web/` 拷到输出目录**，也不再有 `CopyWebOnBuild` 目标。

## 四、发布为单文件 exe（便于分发）

```bat
cd wpf
dotnet publish InkRead.slnx -c Release -r win-x64 ^
  -p:PublishSingleFile=true -p:SelfContained=true ^
  -p:IncludeNativeLibrariesForSelfContained=true
```

- `SelfContained=true`：目标机器无需装 .NET 8 运行时（但 WebView2 Runtime 仍需系统提供）。
- 前端已内嵌，发布目录无需额外的 `web/`。
- 若不想自带 .NET 运行时，去掉 `SelfContained` 相关参数，要求用户自行安装 .NET 8 运行时。

## 五、运行时的关键行为

- **前端来源（优先级）**：
  1. 环境变量 `INKREAD_WEB_DIR` 指向的磁盘目录（**仅开发时使用**，改完刷新即生效）；
  2. 否则一律用**内嵌资源**（自包含，默认路径）。
- **WebView2 初始化**：显式调用 `CoreWebView2Environment.CreateAsync` +
  `EnsureCoreWebView2Async`。**不要依赖隐式自动初始化**——实测在部分环境（Edge 154 运行时 /
  WebView2 SDK 1.0.2792.45）隐式初始化不会触发，表现为「窗口纯白、无任何报错」。
- **启动日志**：exe 同级 `InkRead.log`（不可写时退回 `%LOCALAPPDATA%\InkRead\inkread-desktop.log`），
  记录运行时版本、本地服务端口、内嵌资源数、导航结果、前端启动自检（`dataset.boot` / JS 错误）。
- **用户数据目录**：`%LOCALAPPDATA%\InkRead\WebView2`。
  IndexedDB（词库、生词本）与 TTS 缓存持久化于此，**重装/升级不会丢数据**。
- **外链处理**：点词弹窗里的「剑桥词典」用 `window.open` 打开外链，
  `NewWindowRequested` 事件将其改为 **系统默认浏览器** 打开，避免在壳内嵌弹窗。

## 六、排查白屏（按顺序）

1. 看 exe 同级 `InkRead.log`：
   - 只有「启动 / XAML 已加载」→ WebView2 初始化卡住或失败（日志会写明原因）；
   - 有「导航完成: success=False」→ 本地服务或端口问题；
   - 有「启动自检」且 `boot != 1` → 前端 JS 出错，日志含 `#js-error` 文本。
2. 确认 WebView2 Runtime 已安装（日志首行会打印版本号）。
3. 需要逐层验证时，可用无 GUI 冒烟测试单独跑本地服务：
   ```bat
   cd ..\tools\server-smoke
   dotnet run --project server-smoke.csproj -- "..\..\web" "port.txt"
   ```
   启动后按 `port.txt` 里的端口访问 `http://127.0.0.1:端口/__proxy?ping=1` 验证转发端点。
